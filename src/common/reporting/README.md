# Reporting layer (`src/common/reporting/`)

Stakeholder-oriented, **offline, standard-library-only** reports generated from the
existing eval suite and the human-review audit log. No model, GPU, or third-party
package is required — this is the same Mode 1 footprint as the rest of the repo.

Each generator returns a `Report` (title + Markdown body + output filename); the CLI
runner writes them into `reports/`.

## Reports ↔ stakeholder roles

| Report (file) | Audience | What it answers | Source of truth |
|---|---|---|---|
| `grading-audit-summary.md` | **Auditor** | How many grades auto-accepted vs. escalated? Override rate (H4)? Why were grades escalated? Which attacks were caught? | Human-review **audit log** |
| `track-comparison.md` | **Product owner** | Track A vs. Track B across the 5 eval dimensions; the H3 escalation head-to-head; robustness by attack category | **Eval suite** (agreement, calibration, bias-fairness, auditability, robustness) |
| `rubric-optimization.md` | **Content author** | Which criteria are most overridden by teachers? Which lean least on rubric content? | Audit log + interp artifacts |
| `interp-findings/interp-findings.md` | **Researcher** | Per-example content vs. spurious attribution; the escalation each signal drives; H3 precision/recall/accuracy | Track A interp artifacts |

## Honesty framing (non-negotiable)

Every report carries an explicit banner where relevant, from a single source of truth
in `common.py`, so the same honest story is told everywhere:

- **Placeholder data** — interpretability figures are synthetic placeholders until a
  real Mode 3 cloud run regenerates the artifacts. The pipeline and escalation logic
  are real; the *numbers* are illustrative until then. Detected automatically via
  `ArtifactBackend.is_placeholder()`.
- **Baseline is a floor, not a promise** — quality figures come from the naive keyword
  baseline and establish a floor the real graders must beat, not a production claim.
- **Not a safety guarantee** — robustness/security measure resistance to a *taxonomy of
  known* attacks only; real protection is defence-in-depth, not a test-pass percentage.
- **The tool proposes; the teacher decides** — every escalated grade requires an
  authoritative, audited human decision.

The offline Track B provider is a mock and is deliberately **excluded** from the
comparison tables, so mock output is never presented as a result. Genuine Track B
numbers require a live API run; genuine Track A numbers require a Mode 3 run.

## Usage

```bash
# Write all four reports into reports/ (from repo root)
python -m src.common.reporting.generate

# Print to stdout instead of writing files
python -m src.common.reporting.generate --stdout

# Seed a small SYNTHETIC demo audit log first, so the audit-derived reports are
# non-empty (clearly labelled as a demo — never real grading history)
python -m src.common.reporting.generate --demo-audit
```

The audit-derived reports read the append-only log at `reports/grading-audit/`. That
log is runtime state (generated by the review flow, e.g. `python -m ui.review_cli`) and
is **gitignored** — only the report Markdown is version-controlled. With an empty log,
the audit reports render honestly with zero counts and a note to run the review flow.

## Programmatic use

```python
from src.common.reporting import (
    build_grading_audit_report,       # (records) -> Report
    build_comparison_report,          # (rubric_id) -> Report
    build_rubric_optimization_report, # (records, rubric_id) -> Report
    build_interp_findings_report,     # (rubric_id) -> Report
)
```

## Scope

Foundational/offline only. Rich dashboards, exports, and product reporting belong in the
separate product repository — this layer demonstrates the *concepts* (which report each
stakeholder needs, and how to frame the numbers honestly) end-to-end and testably.
